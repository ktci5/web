# ktci5.kr — 디스코드 자동 인증 Worker

> KT CI5 스터디 운영 저장소는 셋으로 나뉩니다.
>
> | 저장소 | 공개 | 내용 |
> | --- | --- | --- |
> | **ktci5/web** (여기) | 공개 | Cloudflare Worker 소스와 운영 스크립트 |
> | [ktci5/study](https://github.com/ktci5/study) | 공개 | 스터디 자료, 자격증 자료, 웹 학습 허브 |
> | ktci5/data | 비공개 | 명단 등 개인정보가 담긴 데이터 |
>
> 실명·디스코드 ID 가 들어간 파일은 **절대 이 저장소에 두지 않습니다.**

KT클라우드 인프라교육 5기 스터디 서버용 Cloudflare Worker.
학생이 링크를 누르거나 서버 안에서 버튼을 누르면 `5기인증` 역할이 바로 부여됩니다.
Ticket Tool 수동 승인을 대체하는 구조입니다.

## Developer Portal 에 넣을 URL

디스코드 [Developer Portal](https://discord.com/developers/applications) → 앱 → **General Information** 에서:

| 항목 | 값 |
| --- | --- |
| 인터랙션 엔드포인트 URL | `https://ktci5.kr/discord/interactions` |
| 연결된 역할 인증 URL | `https://ktci5.kr/discord/linked-role` |
| 이용 약관 URL | `https://ktci5.kr/terms` |
| 개인정보 보호 정책 URL | `https://ktci5.kr/privacy` |

> 인터랙션 엔드포인트는 저장할 때 디스코드가 서명된 PING 과 **일부러 잘못 서명한 요청**을 함께 보내 검증합니다.
> 먼저 `DISCORD_PUBLIC_KEY` 시크릿을 등록하고 배포한 뒤에 주소를 저장하세요. 순서가 반대면 저장이 거부됩니다.

| GET | `/discord/linked-role` | 연결된 역할 인증 시작 |

### 인증 경로 3가지

1. **웹** — `ktci5.kr` 접속 → 디스코드 로그인 → 역할 부여
2. **슬래시 명령** — 서버에서 `/인증` 입력 → 즉시 역할 부여 (비공개 응답)
3. **버튼** — 운영진이 `/인증패널` 로 게시한 패널의 **인증하기** 버튼 클릭

2·3번은 게이트웨이 봇 없이 인터랙션 엔드포인트(HTTP POST)로만 동작합니다.

## 1. 디스코드 설정

1. **OAuth2** 탭 → **Redirects** 에 세 개 모두 추가 후 Save
   - `https://ktci5.kr/discord/callback`
   - `https://ktci5.kr/discord/linked-role/callback`
   - `https://ktci5.kr/callback` (기존 링크 호환용)
2. 같은 탭에서 **Client ID** 확인, **Client Secret** 은 *Reset Secret* 으로 새로 발급받아 복사
3. **General Information** 탭에서 **Public Key** 복사 (인터랙션 서명 검증용)
4. 서버에서 개발자 모드를 켜고 `5기인증` **역할 ID** 복사 (서버 설정 → 역할 → 우클릭 → ID 복사)
5. 서버 설정 → 역할 목록에서 **봇 역할을 `5기인증` 보다 위로** 드래그
   (디스코드는 봇이 자기보다 아래 있는 역할만 부여할 수 있습니다)
6. 봇 초대 권한에 **역할 관리(Manage Roles)** 포함 확인 — 없으면 `https://ktci5.kr/discord/bot` 으로 재초대

## 2. Cloudflare 설정

```bash
npm install
npx wrangler login          # 최초 1회
bash scripts/setup-secrets.sh
npm run deploy
```

`scripts/setup-secrets.sh` 가 아래 5개를 순서대로 물어봅니다. 값은 코드/저장소에 남지 않습니다.

| 시크릿 | 값 |
| --- | --- |
| `DISCORD_CLIENT_ID` | OAuth2 탭의 Client ID (= Application ID) |
| `DISCORD_CLIENT_SECRET` | OAuth2 탭의 Client Secret |
| `DISCORD_BOT_TOKEN` | Bot 탭의 토큰 |
| `DISCORD_ROLE_ID` | `5기인증` 역할 ID |
| `DISCORD_PUBLIC_KEY` | General Information 탭의 Public Key |

공개돼도 되는 값은 `wrangler.toml` 의 `[vars]` 에 있습니다.

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `DISCORD_GUILD_ID` | `1541782724363427922` | 서버(길드) ID |
| `REDIRECT_URI` | `https://ktci5.kr/discord/callback` | OAuth2 리다이렉트 URI |
| `LINKED_ROLE_REDIRECT_URI` | `https://ktci5.kr/discord/linked-role/callback` | 연결된 역할 콜백 |
| `DISCORD_INVITE_URL` | (비어 있음) | `/discord/` 가 보낼 서버 초대 링크 |
| `AUTO_JOIN` | `"false"` | `"true"` 면 서버 미참여자도 자동 참여 + 역할 부여 |

`AUTO_JOIN="true"` 로 바꾸면 OAuth 스코프가 `identify guilds.join` 으로 확장되어,
아직 서버에 안 들어온 사람도 링크 하나로 참여 + 인증이 동시에 끝납니다.
바꾼 뒤에는 반드시 재배포하세요.

배포 후 `https://ktci5.kr/discord/status` 가 `{"ok":true}` 를 주면 설정 완료입니다.

## 3. 명령 · 연결된 역할 등록

배포 후 한 번만 실행하면 됩니다. `.dev.vars` 또는 환경변수에서 값을 읽습니다.

```bash
cp .dev.vars.example .dev.vars   # 값 채워넣기 (커밋 금지)
npm run setup:discord            # 아래 세 가지를 순서대로 실행
```

| 명령 | 하는 일 |
| --- | --- |
| `npm run register:urls` | Portal 의 URL 4개(인터랙션·연결된 역할·약관·정책)를 API 로 설정 |
| `npm run register:commands` | `/인증`, `/인증패널` 슬래시 명령 등록 |
| `npm run register:metadata` | 연결된 역할 메타데이터 스키마 등록 |

`register:urls` 는 먼저 `/discord/status` 와 서명 없는 POST 응답을 확인해서, 배포가
준비되지 않았으면 실행을 멈춥니다. 준비 안 된 상태로 인터랙션 URL 을 저장하면
디스코드 검증이 반드시 실패하기 때문입니다. 대시보드에서 손으로 넣어도 되지만,
이 명령을 쓰면 오타와 순서 실수가 없습니다.

메타데이터를 등록하면 **서버 설정 → 역할 → 링크 설정**에서 이 앱의 조건
(`5기 인증 = 참`, `기수 = 5`)을 골라 자동 역할을 걸 수 있습니다.

## 4. GitHub 자동 배포

`main` 에 푸시하면 `.github/workflows/deploy.yml` 이 빌드 → 배포를 수행합니다.
저장소 Settings → Secrets and variables → Actions 에 아래 두 개를 등록하세요.
(등록 전까지 배포 단계는 경고만 남기고 건너뜁니다.)

| 시크릿 | 발급처 |
| --- | --- |
| `CLOUDFLARE_API_TOKEN` | Cloudflare 대시보드 → My Profile → API Tokens → *Edit Cloudflare Workers* 템플릿 |
| `CLOUDFLARE_ACCOUNT_ID` | Workers & Pages 대시보드 우측의 Account ID |

## 데이터 취급

데이터베이스를 두지 않습니다. 디스코드에서 받은 사용자 ID·사용자명과 액세스 토큰은
요청을 처리하는 동안 메모리에서만 쓰이고 저장되지 않습니다. 자세한 내용은 `/privacy` 참고.

## 5. 앱과 서버를 잇는 세 지점

앱(Developer Portal)과 서버는 아래 세 곳에서 연결됩니다. 하나라도 빠지면 그 경로만 조용히 동작하지 않습니다.

| 연결 | 하는 일 | 확인 방법 |
| --- | --- | --- |
| **봇을 서버에 초대** | 역할을 실제로 부여하는 주체 | 서버 멤버 목록에 봇이 보임 |
| **인터랙션 엔드포인트 URL** | 서버의 명령·버튼을 Worker 로 전달 | Portal 저장 시 검증 통과 |
| **슬래시 명령 등록** | 서버에 `/인증` 등을 노출 | 채팅창에 `/` 입력 시 목록에 보임 |

초대 URL은 `https://ktci5.kr/discord/bot` 이 만들어줍니다. 직접 만들 때는 반드시
`permissions` 에 **MANAGE_ROLES** 를 포함하고 `integration_type=0`(서버 설치)이어야 합니다.
포털의 URL 생성기는 이 둘을 빠뜨리기 쉽습니다.

초대 후 **서버 설정 → 역할**에서 봇 역할을 `5기인증` 보다 위로 올리세요.
권한이 있어도 역할 순서가 아래면 부여가 403 으로 실패합니다.

## 6. 기능 추가하기

명령과 버튼은 `src/index.js` 의 `handleCommand` / `handleComponent` 에서 분기합니다.
새 기능은 대부분 이 두 곳과 `scripts/register-commands.mjs` 만 건드리면 됩니다.

### 새 슬래시 명령 추가

`scripts/register-commands.mjs` 의 `COMMANDS` 에 정의를 넣고,

```js
{
  name: '내정보',
  description: '내 5기 인증 상태를 확인합니다.',
  dm_permission: false,
},
```

`src/index.js` 의 `handleCommand` 에 처리를 추가합니다.

```js
if (name === '내정보') {
  const user = interaction.member?.user || interaction.user;
  const verified = await hasVerifiedRole(user.id, env);
  return ephemeral(verified ? '✅ 인증 완료 상태입니다.' : '아직 인증 전입니다. `/인증` 을 실행해주세요.');
}
```

그다음 배포하고 명령을 다시 등록합니다.

```bash
npx wrangler deploy
npm run register:commands
```

서버(길드) 명령은 즉시 반영됩니다. 전역 명령으로 바꾸면 최대 1시간 걸립니다.

### 새 버튼 추가

패널 응답의 `components` 에 버튼을 넣고 `custom_id` 를 정한 뒤,

```js
{ type: 2, style: 1, label: '내 상태 확인', custom_id: 'ktci5_whoami' }
```

`handleComponent` 에서 같은 `custom_id` 를 분기하면 됩니다. 버튼은 명령 재등록이 필요 없고 배포만 하면 반영됩니다.

### 3초 제한

인터랙션은 **3초 안에** 응답해야 합니다. 디스코드 API 호출이 여러 번 필요한 기능이라면
먼저 `{ type: 5 }`(지연 응답)를 반환해 로딩 상태를 띄우고, 이어서
`PATCH /webhooks/{application_id}/{token}/messages/@original` 로 결과를 채워 넣으세요.
현재 명령들은 API 호출이 한 번이라 즉시 응답으로 충분합니다.

### 로컬에서 인터랙션 테스트하기

디스코드는 공개 URL 로만 인터랙션을 보냅니다. 로컬 개발 중에는 터널로 임시 주소를 만드세요.

```bash
npm run dev                                   # 터미널 1 — localhost:8787
cloudflared tunnel --url http://localhost:8787  # 터미널 2 — 임시 https 주소 발급
```

발급된 `https://xxx.trycloudflare.com/discord/interactions` 를 Portal 의 인터랙션
엔드포인트에 잠시 넣으면, 서버에서 명령을 실행할 때 로컬 코드가 실행됩니다.
`.dev.vars` 에 `DISCORD_PUBLIC_KEY` 가 있어야 서명 검증이 통과합니다.
테스트가 끝나면 Portal 주소를 `https://ktci5.kr/discord/interactions` 로 되돌리세요.

### 웹 페이지 수정

랜딩·성공·오류 화면은 `renderPage`, 약관·정책은 `renderDoc` 이 그립니다.
공통 스타일은 `BASE_CSS` 한 곳에 있습니다. 배포만 하면 즉시 반영됩니다.

## 7. 스터디 일정 (구글 캘린더 연동)

디스코드에서 일정을 등록하고, 오늘 일정을 불러옵니다.

| 명령 | 하는 일 |
| --- | --- |
| `/일정등록` | 구글 캘린더에 스터디 일정을 만들고 채널에 카드로 공지 |
| `/오늘일정` | 오늘 캘린더 일정을 불러와 본인에게만 표시 |

```
/일정등록 제목:쿠버네티스 3회차 날짜:9/10 시작시각:22시 진행시간:2
          장소:강남 스터디카페 지역:서울 주제:쿠버네티스 온라인:false
```

날짜는 `2026-09-10`, `9/10`, `9월 10일` 을 모두 받습니다. 연도를 생략하면 올해로 봅니다.
시각은 `22:00`, `22시`, `22` 형식을 받습니다. 시간대는 `Asia/Seoul` 기준입니다.
`2월 30일` 처럼 존재하지 않는 날짜는 거부합니다.

### 구조

Worker 가 서비스 계정 JWT 를 직접 서명해 액세스 토큰을 받고, 구글 캘린더 API 를
호출합니다 (RFC 7523). 중간 서버가 없습니다.

```
디스코드 ──▶ Worker(ktci5.kr) ──▶ Google Calendar API
                  │
                  └─ 서비스 계정 개인키로 JWT 서명 → 액세스 토큰
```

캘린더 호출이 3초를 넘길 수 있어 지연 응답(`type: 5`)을 먼저 보내고,
결과가 오면 원본 메시지를 수정합니다. 액세스 토큰과 서명 키는 아이솔레이트
수명 동안 캐시하므로 매 요청마다 다시 서명하지 않습니다.

### 설정

**1. 서비스 계정 만들기**

<https://console.cloud.google.com> → 프로젝트 생성(또는 선택)

- **API 및 서비스 → 라이브러리** → `Google Calendar API` 사용 설정
- **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → 서비스 계정**
- 만들어진 서비스 계정 → **키** 탭 → **키 추가 → 새 키 만들기 → JSON** → 다운로드

**2. 키를 Worker 에 등록**

```bash
node scripts/setup-google.mjs ~/Downloads/받은키.json
```

PEM 개인키를 base64 한 줄로 바꿔 `GOOGLE_SA_EMAIL`, `GOOGLE_SA_PRIVATE_KEY_B64`
두 시크릿으로 올립니다. 키 파일은 저장소로 복사하지 않습니다.

**3. 캘린더를 서비스 계정과 공유**

구글 캘린더 → 대상 캘린더 → **설정 및 공유**

- **특정 사용자와 공유** → 서비스 계정 이메일 추가 → 권한 **변경 및 공유 관리**
- 같은 화면의 **캘린더 통합** → **캘린더 ID** 복사

**4. 캘린더 ID 를 넣고 배포**

```bash
# wrangler.toml 의 GOOGLE_CALENDAR_ID 에 붙여넣기
npx wrangler deploy
npm run register:commands
```

설정 여부는 `/discord/status` 의 `calendar` 필드로 확인할 수 있습니다.

> 서비스 계정에는 사람이 쓰는 기본 캘린더가 없습니다. 반드시 실제 캘린더를
> 공유하고 그 캘린더 ID 를 지정해야 합니다. `primary` 는 동작하지 않습니다.

## 8. 명단 기반 인증

공통 초대 링크 하나로 들어온 사람을 명단(`list.csv`)과 대조해 자동으로 걸러냅니다.
클릭 수를 최소화하는 것이 목표라, 명단에 계정이 있으면 버튼 한 번으로 끝납니다.

### 흐름

```
/인증 또는 인증 버튼
   │
   ├─ 명단에 디스코드 계정 있음  → 즉시 역할 부여 (추가 클릭 0회)
   ├─ 계정은 없고 이름은 있음    → 이름 목록에서 본인 선택 → 역할 부여
   └─ 명단에 아예 없음          → 운영진 채널에 승인 요청 → 운영진이 버튼 클릭
```

계정 대조는 디스코드 사용자 ID 를 먼저 보고, 없으면 사용자명으로 맞춰봅니다.
ID 는 화면에 표시하지 않고 내부에서만 씁니다.

이름을 고르면 그 이름은 해당 계정에 묶여(`claims`) 다른 사람이 다시 고를 수 없습니다.
역할 부여가 실패하면 묶임을 되돌리므로 본인이 재시도할 수 있습니다.
이름으로 인증한 건은 운영진 채널에 기록이 남아 나중에 확인할 수 있습니다.

### 명단 올리기

`list.csv` 는 **실명이 들어 있어 저장소에 커밋하지 않습니다**(`.gitignore`).
명단은 KV 에만 저장되고, Worker 는 인증 시점에만 조회합니다.

```bash
node scripts/upload-roster.mjs list.csv
```

CSV 컬럼은 디스코드 멤버 내보내기 형식을 그대로 씁니다.

| 컬럼 | 쓰임 |
| --- | --- |
| `id` | 디스코드 사용자 ID — 있으면 클릭 없이 즉시 인증 |
| `username` | 디스코드 사용자명 — ID 가 없을 때 보조 대조 |
| `nickname` | 실명 — 본인이 목록에서 고를 때 표시 |

명단이 바뀌면 CSV 를 갱신하고 위 명령만 다시 실행하면 됩니다. 배포는 필요 없습니다.

### 운영진 채널

`ADMIN_CHANNEL_ID` 시크릿에 채널 ID 를 넣으면 그 채널로 승인 요청이 갑니다.
설정하지 않으면 승인 요청 대신 "운영진에게 문의해주세요" 안내만 표시됩니다.

```bash
printf '<채널ID>' | npx wrangler secret put ADMIN_CHANNEL_ID
```

승인 버튼은 **역할 관리 또는 관리자 권한**을 가진 사람만 누를 수 있습니다.

## 9. 채널 안내와 공지 멘트

> 역할 이름은 `src/index.js` 의 `ROLE_NAME` 상수 한 곳에서 관리합니다.
> 서버에서 역할명을 바꾸면 이 값만 고치고 배포하면 안내 문구 전체가 따라갑니다.

### 웹 안내 페이지 (인증자 전용)

디스코드를 처음 쓰는 사람 기준으로 작성했습니다. 구성은 이렇습니다.

| 섹션 | 내용 |
| --- | --- |
| 먼저 해두면 좋은 것 | 알림 켜기, 자기소개, 관심 채널 둘러보기 |
| 디스코드 처음이신가요 | 채널 찾기, 메시지, 스레드, 파일, 코드 블록, 알림, 음성, 검색 |
| 명령어 쓰는 법 | `/` 입력 → 목록 → Tab 으로 항목 이동 |
| 채널별 안내 | 채널마다 **무엇을 하는 곳 · 어떻게 쓰는지 · 실제 예시** |
| 자료실 | 드라이브 폴더 링크와 업로드·태그 방법 |
| 막히면 | 인증·채널·드라이브 문제별 대처 |

내용은 `src/index.js` 의 `DISCORD_BASICS`, `CHANNEL_GUIDE`, `BOT_COMMANDS`
세 표에 있습니다. `CHANNEL_GUIDE` 의 각 항목은 `what`(무엇), `how`(사용법 목록),
`example`(예시) 을 가집니다.

<https://ktci5.kr/guide> 에 채널별 사용법이 정리되어 있습니다.
**인증을 마친 사람만 볼 수 있습니다.** 인증하지 않은 접근은 인증 흐름으로
보냈다가 끝나면 자동으로 이 페이지로 돌아옵니다.

통행증은 클라이언트 시크릿으로 HMAC 서명한 쿠키(`ktci5_pass`, 30일)입니다.
값을 위조하거나 만료된 쿠키는 통과하지 못합니다.

인증 완료 화면의 첫 번째 버튼이 이 페이지로 이어지고, 디스코드에서 인증한
경우에도 완료 메시지에 링크가 함께 나갑니다.

서버 구조가 바뀌면 `src/index.js` 의 `CHANNEL_GUIDE` 표만 고치고 배포하면 됩니다.

### 채널 주제 (한 줄 설명)

채널 이름 옆에 뜨는 한 줄 설명을 일괄 설정합니다.

```bash
npm run topics                                  # 미리보기
node scripts/set-channel-topics.mjs --apply     # 반영
```

문구는 스크립트 상단의 `TOPICS` 표에서 고칩니다. 설정 대상에 없는 채널과
서버에서 찾지 못한 채널을 함께 알려주므로, 채널을 새로 만들어도 놓치지 않습니다.

봇이 볼 수 없는 채널은 403 이 나며 건너뜁니다. 그 채널의 **채널 편집 → 권한**
에서 봇 역할을 추가하고 **채널 보기**를 허용한 뒤 다시 실행하세요.

설명은 세 곳이 깊이를 나눠 맡습니다.

| 위치 | 분량 | 역할 |
| --- | --- | --- |
| 채널 주제 | 한 줄 | 들어온 순간 "여기가 뭐 하는 곳" |
| `#index` 메시지 | 카테고리별 | 서버 전체 지도 |
| `/guide` | 상세 | 인증 후 차분히 읽는 안내 |

### 자격증 카테고리

자격증은 종목이 많아 채널 하나로는 좁아, `📁 08. 자격증` 카테고리로 분리했습니다.

| 채널 | 다루는 종목 |
| --- | --- |
| `#📜-자격증` | 공통 — 접수 일정, 시험 후기, 종목 고민 |
| `#☁️-aws-자격증` | CLF · SAA · SOA · DVA |
| `#☁️-클라우드-자격증` | KT Cloud · NCP · Azure · GCP |
| `#🌐-네트워크-자격증` | 네트워크관리사 · CCNA |
| `#🐧-리눅스-자격증` | 리눅스마스터 · LPIC · RHCSA |
| `#⎈-쿠버네티스-자격증` | CKA · CKAD · CKS |
| `#📘-정보처리기사` | 필기 · 실기 |
| `#🔐-정보보안기사` | 기사 · 산업기사 |
| `#🗄️-sqld-자격증` | SQLD · SQLP |

`03. 분야별 스터디` 의 채널 이름과 겹치지 않도록 `-자격증` 을 붙였습니다.
디스코드는 같은 이름을 허용하지만, 스크립트가 이름으로 채널을 식별하므로
겹치면 엉뚱한 채널을 건드리게 됩니다.

### 채널별 고정 안내

채널마다 그 채널의 사용법을 담은 안내를 게시하고 고정합니다. 채널 주제는 한 줄이라
처음 온 사람이 놓치기 쉬워, 들어오자마자 보이는 고정 메시지로 보완합니다.

```bash
npm run intros                                   # 초안 확인
node scripts/post-channel-intros.mjs --post      # 전체 게시 + 고정
node scripts/post-channel-intros.mjs --post 💻-리눅스   # 한 채널만
```

내용은 스크립트의 `INTROS` 표에 있습니다. 분야별 스터디·지역모임·그룹처럼
형태가 같은 채널은 `study()`, `region()`, `group()` 헬퍼로 만들어 문구가
어긋나지 않게 했습니다.

각 안내는 **무엇을 하는 곳 · 이렇게 써주세요 · 예시** 세 부분이고, 하단에
`ktci5.kr/guide` 링크가 붙습니다.

다시 실행하면 이전에 올린 안내를 지우고 새로 올립니다. 본문에 보이지 않는 표식을
넣어 이 스크립트가 올린 메시지만 골라내므로, 사람이 쓴 글은 건드리지 않습니다.

### 디스코드 채널 멘트

`scripts/post-messages.mjs` 가 세 채널의 안내 메시지를 관리합니다.

| 키 | 채널 | 내용 |
| --- | --- | --- |
| `welcome` | `#📢-공지사항` | 환영 인사 + 시작하는 방법 3단계 |
| `index` | `#index` | 카테고리별 채널 안내 |
| `gate` | `#🔒-대기실` | 인증 안내 + **인증하기 버튼** |

**기본은 초안 출력입니다. 아무것도 보내지 않습니다.**

```bash
npm run messages              # 초안만 확인
node scripts/post-messages.mjs --post          # 세 개 모두 게시
node scripts/post-messages.mjs --post gate     # 대기실 안내만 게시
```

`gate` 메시지에는 인증 버튼이 함께 올라가므로, 이걸 게시하면 `/인증패널` 을
따로 실행할 필요가 없습니다. 문구는 스크립트 상단의 `MESSAGES` 배열에서 고칩니다.

메시지를 수정하고 다시 게시하면 새 메시지가 추가됩니다. 기존 메시지는
디스코드에서 직접 지우거나, 채널을 비우고 다시 올리세요.

## 10. 자료실 (구글 드라이브)

교육과정에서 공유한 드라이브 폴더 링크를 안내에 노출합니다. 봇이 드라이브를
직접 읽지는 않습니다.

폴더 소유자가 교육과정 쪽이라 서비스 계정에 공유 권한을 줄 수 없었고,
서비스 계정은 저장 용량이 0 이라 업로드도 불가능합니다. 링크 안내만으로
충분한 범위라 연동 대신 링크 노출을 택했습니다.

폴더 구성은 이렇습니다.

| 이름 | 용도 |
| --- | --- |
| Ⅰ. 훈련 자료 | 강의·실습 자료 |
| Ⅱ. 챌린저 제출 폴더 | 과제 제출 |
| Ⅲ. 훈련수당 신청 | 수당 관련 서류 |
| 전체 모음 (KT CI5) | 위 세 폴더 바로가기를 모아둔 폴더 |

드라이브 폴더 링크는 **디스코드 `#📚-자료공유` 채널에만** 둡니다.
공개 저장소(`ktci5/web`, `ktci5/study`)와 웹 안내 페이지(`ktci5.kr`)에는 노출하지 않습니다.
스터디 자료 폴더 주소가 검색이나 저장소 열람으로 새어나가지 않게 하기 위함입니다.

| 위치 | 드라이브 링크 |
| --- | --- |
| `#📚-자료공유` 고정 메시지 | 있음 — `scripts/post-messages.mjs` 의 `DRIVE_FOLDERS` |
| `/자료함` 명령 응답 | 있음 — 본인에게만 보이는 응답 |
| `ktci5.kr` 웹 페이지 | 없음 |
| 공개 저장소 문서 | 없음 |

```bash
node scripts/post-messages.mjs --post drive      # 채널 안내 갱신
```

전체 모음 폴더는 운영자 소유라 서비스 계정도 읽고 쓸 수 있습니다. 다만 그 안의
교육과정 항목은 원본으로 가는 **바로가기**여서, 바로가기 너머의 파일 목록까지는
읽지 못합니다.

### 채널별 폴더

디스코드 채널 구조를 드라이브 폴더로 옮겨둡니다. 채널 목록을 디스코드에서 직접
읽으므로, 채널을 추가한 뒤 다시 실행하면 새 폴더만 만들어집니다.

```bash
npm run drive                                    # 미리보기
node scripts/create-drive-folders.mjs --apply    # 생성
```

대상 카테고리는 스크립트의 `INCLUDE` 에서 정합니다. 공지·인증처럼 파일이
쌓일 일이 없는 카테고리는 제외되어 있습니다.

서비스 계정은 저장 용량이 0 이라 **파일은 올리지 못하지만 폴더는 만들 수
있습니다**(폴더는 크기가 없기 때문). 파일은 각자 드라이브에서 올립니다.

### 자료 명령

| 명령 | 하는 일 |
| --- | --- |
| `/자료함` | 지금 채널의 드라이브 폴더 링크 |
| `/자료보기` | 그 폴더의 파일 목록 (최근 수정순, 태그 함께 표시) |
| `/자료검색` | 이름·설명·문서 내용에서 검색. `이채널만` 옵션으로 범위 축소 |
| `/스터디자료` | 깃허브 `ktci5/study` 저장소를 디스코드에서 탐색 |

### 깃허브 자료 (`/스터디자료`)

`ktci5/study` 의 파일 목록을 디스코드에서 바로 봅니다. 폴더는 옆에 다음 명령이
함께 표시되어 이어서 들어갈 수 있습니다.

```
/스터디자료                          저장소 루트
/스터디자료 폴더:스터디자료/리눅스      해당 폴더
```

한글 폴더명 때문에 경로는 구간별로 인코딩합니다(`encodeRepoPath`).
인증 없는 깃허브 API 는 시간당 호출 수가 제한되므로 결과를 KV 에 10분 캐시합니다.
비공개 저장소는 조회할 수 없습니다 — `ktci5/data` 는 의도적으로 대상이 아닙니다.

연결된 폴더가 없는 채널에서는 전체 자료실로 안내합니다.

### 태그

드라이브에는 태그 기능이 없어 **파일 이름이나 설명의 `#태그`** 를 태그로 씁니다.
`/자료보기` 는 파일마다 태그를 함께 보여주고, `/자료검색` 은 `#쿠버네티스` 처럼
태그로도 찾습니다. 구글 문서 본문까지 검색되므로 태그를 안 붙여도 대체로 찾힙니다.

설명은 드라이브에서 파일 우클릭 → **파일 정보 → 세부정보** 에서 넣습니다.

### 변경 알림

15분마다 드라이브 변경을 확인해 `DRIVE_NOTIFY_CHANNEL_ID` 채널에 알립니다.

```toml
[triggers]
crons = ["*/15 * * * *"]
```

새로 올라오거나 수정된 파일과 **휴지통으로 옮겨진 파일**을 함께 알립니다.
편집 권한을 열어두면 누구나 파일을 지울 수 있으므로, 무엇이 사라졌는지
바로 알 수 있게 하기 위한 장치입니다. 휴지통 항목은 30일 안에 복구됩니다.

변경 위치를 추적하는 페이지 토큰은 KV 의 `drive:pageToken` 에 둡니다.
처음 실행할 때는 그 시점부터 감시를 시작하고 과거 변경은 알리지 않습니다.

> 학생이 링크를 열 수 있는지는 교육과정의 공유 설정에 달려 있습니다.
> 과정에 등록된 구글 계정으로만 열립니다. 전원이 접근하지 못한다면 운영자
> 소유로 새 폴더를 만들어 "링크가 있는 모든 사용자"로 공유하는 편이 낫습니다.

## 11. 학습 문서 (ktci5.kr/study)

인증을 마친 사람만 볼 수 있는 학습 문서입니다. 내용은 `src/` 의 모듈에 있습니다.

| 경로 | 문서 | 모듈 |
| --- | --- | --- |
| `/study` | 자료 목차 | `src/index.js` 의 `STUDY_MATERIALS` |
| `/study/linux` | 리눅스 CLI 심층 가이드 | `src/study-linux.js` |
| `/study/infra` | 이 서버는 어떻게 돌아가나 | `src/study-infra.js` |

### 왜 이 서버 자체를 교재로 쓰는가

인프라 과정에서 배우는 개념(DNS·엣지·서버리스·CI/CD·OAuth·시크릿 관리)이
이 시스템에 전부 들어 있습니다. 교재 속 그림이 아니라 **동작하는 실물**이라
수강생이 명령을 직접 쳐보며 확인할 수 있습니다.

`/study/infra` 는 네 단계로 나뉩니다.

| 단계 | 내용 |
| --- | --- |
| L1 기초 | 구조도와 비유. 용어를 몰라도 흐름이 그려지는 수준 |
| L2 중급 | `dig`, `curl -I` 로 직접 확인. OAuth 실제 순서 |
| L3 심화 | 왜 이 설계를 골랐고 무엇을 포기했는지 |
| L4 마스터 | `wrangler.toml` 해설, 서명 검증, 3초 제한, KV 설계, 롤백 |

L4 에는 **자동 배포로 시크릿이 사라진 실제 사고**를 사례로 넣었습니다.
"코드와 비밀을 분리하라"는 원칙이 어디서 깨지는지 보여주는 자료입니다.
운영 절차(복구 명령)도 이 단계에 있습니다.

## 12. 미리보기 링크 (강사·운영진용)

디스코드 가입 없이 학습 문서를 볼 수 있는 통로입니다. 강사님께 공유하거나
외부에 소개할 때 씁니다.

```
https://ktci5.kr/preview?key=<PREVIEW_KEY>
```

링크로 들어오면 14일짜리 통행증 쿠키가 발급되고, 그동안 `/guide`, `/study`,
`/study/infra`, `/study/linux` 를 그대로 볼 수 있습니다. 열쇠가 없거나 틀리면 403 입니다.

```bash
# 열쇠 재발급 (기존 링크는 즉시 무효)
printf '%s' "$(openssl rand -hex 16)" | npx wrangler secret put PREVIEW_KEY
```

> 열쇠는 링크에 담겨 전달되므로 **공개 채널에 올리지 마세요.** 개인 메시지나
> 메일로만 보냅니다. 유출이 의심되면 위 명령으로 재발급하면 기존 링크가 끊깁니다.

## 13. 스터디 공간 구성

`ktci5.kr/discord` 는 초대 링크로 넘기기만 하지 않고, **세 곳이 어떻게
이어지는지** 보여주는 입구입니다. 각자 맡는 일이 다릅니다.

| 곳 | 맡는 일 | 잇는 방법 |
| --- | --- | --- |
| 디스코드 | 그때그때 묻고 답한다 | 분야별·지역별 채널 |
| 깃허브 | 정리해서 남긴다 | `/스터디자료` 로 디스코드에서 조회 |
| 구글 드라이브 | 파일을 주고받는다 | 채널마다 같은 이름의 폴더, `/자료함` |

```
디스코드에서 묻고 → 드라이브에 파일 두고 → 깃허브에 정리해 남기고
```

대화는 흘러가고 파일은 쌓이기만 하므로, **정리된 것은 깃허브에 남기는**
흐름을 의도했습니다. 채널과 드라이브 폴더가 이름까지 1:1 로 맞아 있어
"이 자료가 어디 있더라" 를 고민하지 않게 했습니다.
