## 계층 구조

컴퓨터는 층으로 되어 있습니다. 위쪽은 사람에게 가깝고 아래로 갈수록 기계에 가깝습니다.

```
        사용자
     Application        ┐
   Operating System     ├ 소프트웨어
       Hardware         ┘ 하드웨어
```

**우리가 명령을 치면 위에서 아래로 내려갔다가 결과가 다시 올라옵니다.**

---

## 운영체제의 세 부분

| 구성 | 하는 일 |
| --- | --- |
| **셸(Shell)** | 사용자의 명령을 받아 해석 |
| **커널(Kernel)** | 실제로 하드웨어를 다룸 |
| **파일시스템** | 데이터를 계층 구조로 보관 |

### 명령 하나가 흐르는 길

```bash
$ ls
```

1. 사용자가 `ls` 를 친다
2. **셸**이 받아서 해석한다
3. **커널**에게 "디렉터리 목록을 달라"고 요청한다
4. 커널이 디스크에서 읽어온다
5. 결과가 셸을 거쳐 화면에 나온다

셸은 통역, 커널은 실무자라고 보면 됩니다.

---

## 커널

**운영체제의 핵심**입니다. 하드웨어를 직접 만지는 유일한 부분이라, 응용 프로그램은
반드시 커널을 거쳐야 합니다.

| 서브시스템 | 맡는 일 |
| --- | --- |
| Process Manager | 프로세스 생성·스케줄링·시그널 |
| Memory Manager | 메모리 할당, 가상 메모리 |
| VFS (가상 파일시스템) | ext4·NFS 등 여러 파일시스템을 같은 방식으로 |
| Device Manager | 디스크·키보드·네트워크 카드 등 장치 |
| Network Manager | 네트워크 프로토콜 |

응용 프로그램이 커널에 요청하는 통로를 **시스템 콜(System Call)** 이라고 합니다.
파일을 열고 읽는 것도 전부 시스템 콜입니다.

### 커널 버전 읽는 법

```bash
$ uname -r
6.12.0
```

| 자리 | 뜻 |
| --- | --- |
| `6` | 주 번호 (major) |
| `12` | 부 번호 (minor) |
| `0` | 패치 수준 |

드라이버나 커널 모듈을 설치할 때 이 버전이 맞아야 합니다.

## 파일시스템

**`/` 를 뿌리로 하는 거꾸로 된 나무 구조**입니다. 윈도우처럼 `C:` `D:` 로 나뉘지
않고, 디스크가 여러 개여도 하나의 나무에 가지처럼 붙습니다.

```
                    /
    ┌───────┬───────┼───────┬───────┐
   opt     etc     var     home    usr
                    │       │       │
                   log    user1    bin
```

| 디렉터리 | 무엇이 있나 |
| --- | --- |
| `/etc` | 설정 파일 |
| `/var` | 자주 바뀌는 것 — 로그, 캐시, 메일 |
| `/var/log` | **로그.** 문제가 생기면 여기부터 |
| `/home` | 사용자 홈 디렉터리 |
| `/usr/bin` | 일반 명령 |
| `/opt` | 추가로 설치한 프로그램 |
| `/proc` | **실제 파일이 아니라 커널 정보** |
| `/dev` | 장치 파일 |

## 하드웨어 구성요소

| 부품 | 하는 일 |
| --- | --- |
| **CPU** | 메모리에 올라온 명령과 데이터를 처리 |
| **RAM** | 실행 중인 프로그램이 올라가는 곳. 전원이 꺼지면 사라짐 |
| **Disk** | 파일·디렉터리·프로그램을 보관. 전원이 꺼져도 남음 |
| **I/O** | 입출력 장치, 네트워크 카드 |

### CPU 아키텍처

| 제조사 | CPU | 운영체제 |
| --- | --- | --- |
| Intel | x86 | Windows / Linux |
| AMD | x86 | Windows / Linux |
| Oracle | UltraSPARC | Solaris / Linux |
| IBM | POWER PC | AIX / Linux |
| HP | PA-RISC / Itanium | HP-UX / Linux |

**아키텍처가 다르면 실행 파일이 호환되지 않습니다.** 요즘은 Apple 실리콘(`arm64`)과
Intel(`x86_64`) 차이로 겪는 일이 많습니다. Mac 에서 빌드한 도커 이미지가 서버에서
안 뜨는 이유가 대개 이것입니다.

```bash
$ uname -m
x86_64
```

### 가상 메모리와 스왑

```
가상 메모리 = RAM + swap
```

RAM 이 부족하면 당장 안 쓰는 부분을 디스크(**swap**)로 잠시 내보냅니다.
덕분에 실제 메모리보다 큰 프로그램도 돌아가지만, **디스크는 RAM 보다 훨씬 느려서
스왑이 자주 일어나면 시스템이 눈에 띄게 느려집니다.**

스왑 사용량이 늘고 있다면 메모리가 부족하다는 신호입니다.

## 시스템 정보 보기

`/proc` 은 진짜 파일이 아니라 **커널이 만들어 보여주는 가상 파일시스템**입니다.
읽으면 지금 상태가 나옵니다.

```bash
$ cat /proc/cpuinfo          # CPU 정보
$ cat /proc/meminfo          # 메모리 상세
$ cat /proc/partitions       # 파티션 목록
$ cat /proc/diskstats        # 디스크 입출력 통계
$ swapon -s                  # 스왑 현황
$ uname -a                   # 커널과 아키텍처 전부
$ cat /etc/*release          # 배포판과 버전
```

사람이 읽기 좋은 형태로는 이쪽이 편합니다.

```bash
$ free -h                    # 메모리 (읽기 쉬운 단위)
$ df -h                      # 디스크 사용량
$ lscpu                      # CPU 요약
$ lsblk                      # 블록 장치 트리
```

> `free` 의 출력을 읽는 법과 흔한 오해는
> [리눅스 CLI 심층 가이드](/study/linux)에 정리되어 있습니다.
> "free 가 적다고 메모리 부족이 아니다" 같은 부분입니다.
