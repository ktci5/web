## 한눈에

| 하고 싶은 일 | 명령 |
| --- | --- |
| **파일 안의 내용**을 찾고 싶다 | `grep` |
| **파일 자체**를 찾고 싶다 | `find` |
| 여러 파일을 하나로 묶고 싶다 | `tar` |
| 용량을 줄이고 싶다 | `gzip` · `bzip2` |

`grep` 과 `find` 를 헷갈리기 쉽습니다. **`grep` 은 파일을 열어 안을 보고, `find` 는 파일을
열지 않고 이름·크기·시간으로 찾습니다.**

## grep — 파일 안의 내용 찾기

```bash
grep [옵션] 패턴 파일명
```

### 자주 쓰는 옵션

| 옵션 | 하는 일 | 언제 쓰나 |
| --- | --- | --- |
| `-n` | 줄 번호를 함께 표시 | 설정 파일에서 위치를 알아야 할 때 |
| `-i` | 대소문자 구분 없이 | `ERROR` 인지 `error` 인지 모를 때 |
| `-v` | 패턴이 **없는** 줄만 | 잡음을 걸러낼 때 |
| `-l` | 파일 이름만 표시 | 어느 파일에 있는지만 알면 될 때 |
| `-c` | 몇 줄 걸렸는지 개수만 | 발생 횟수를 셀 때 |
| `-w` | 단어 단위로 일치 | `test` 가 `testing` 에 걸리지 않게 |

### 실제로 이렇게 씁니다

```bash
# 설정 파일에서 포트 설정이 몇 번째 줄인지
grep -n "port" /etc/nginx/nginx.conf

# 주석과 빈 줄을 걷어내고 실제 설정만 보기
grep -v "^#" /etc/ssh/sshd_config | grep -v "^$"

# 로그에서 에러만, 대소문자 무시하고
grep -i "error" /var/log/messages

# 어느 파일에 그 설정이 들어 있는지
grep -rl "DocumentRoot" /etc/httpd/
```

두 번째 예시가 실무에서 특히 유용합니다. 설정 파일은 대부분이 주석이라
**`-v` 로 두 번 걸러내면** 실제로 켜진 설정만 남습니다.

### 정규 표현식

`grep` 의 패턴에는 규칙을 쓸 수 있습니다. 자연어를 기호로 표현하는 방식이라
**정규 표현식(regular expression)** 이라고 부릅니다.

| 기호 | 의미 | 예 |
| --- | --- | --- |
| `^문자열` | 그 문자열로 **시작**하는 줄 | `^root` |
| `문자열$` | 그 문자열로 **끝나는** 줄 | `bash$` |
| `.` | 아무 글자 하나 | `r..t` → `root`, `rest` |
| `*` | 앞의 것이 0번 이상 반복 | `ab*c` → `ac`, `abc`, `abbc` |
| `\+` | 앞의 것이 1번 이상 반복 | `ab\+c` → `abc`, `abbc` (`ac` 는 안 됨) |
| `[abc]` | 괄호 안 글자 중 하나 | `[aeiou]` |
| `[^abc]` | 괄호 안 글자가 **아닌** 것 | `[^0-9]` |
| `\{2,5\}` | 2번 이상 5번 이하 반복 | `[0-9]\{3\}` |
| `\|` | 또는 | `error\|fail` |
| `\<` `\>` | 단어의 시작과 끝 | `\<log\>` |

**POSIX 문자 클래스**를 쓰면 읽기 쉬워집니다. 대괄호 **안에서** 씁니다.

| 클래스 | 같은 뜻 |
| --- | --- |
| `[:alpha:]` | `[A-Za-z]` |
| `[:digit:]` | `[0-9]` |
| `[:alnum:]` | `[A-Za-z0-9]` |
| `[:space:]` | 공백·탭·개행 등 |
| `[:blank:]` | 공백과 탭만 |

```bash
# 소문자로만 이뤄진 단어 찾기
grep "[[:lower:]]\+" file.txt

# 세 자리 숫자 찾기
grep "[[:digit:]]\{3\}" access.log
```

대괄호가 두 겹인 것에 주의하세요. `[:digit:]` 자체가 클래스 표기라
**바깥에 `[ ]` 를 한 번 더** 감싸야 합니다.

## find — 파일 자체 찾기

```bash
find 경로 조건 동작
```

조건을 여러 개 쓰면 **모두 만족하는 것**만 찾습니다(AND). 하나만 만족하면 되는 게
아니라는 점을 기억하세요.

### 조건

| 조건 | 찾는 대상 |
| --- | --- |
| `-name "파일명"` | 이름이 일치. `*` `?` 를 쓸 때는 **따옴표로 감싸기** |
| `-type f` / `-type d` | 파일 / 디렉터리 |
| `-size [+\|-]n` | 크기. `n` 은 512바이트 블록 |
| `-mtime [+\|-]n` | 수정 시각. `+7` 은 7일보다 이전, `-7` 은 7일 이내 |
| `-atime [+\|-]n` | 접근 시각 |
| `-user 계정` | 소유자 |
| `-perm 권한` | 권한 비트 |

`+` 와 `-` 의 방향이 헷갈립니다. **`+` 는 그보다 오래된 것, `-` 는 그보다 최근 것**입니다.

### 찾은 뒤 무엇을 할지

| 동작 | 하는 일 |
| --- | --- |
| `-print` | 경로를 출력 (기본값이라 생략 가능) |
| `-ls` | 상세 정보까지 출력 |
| `-exec 명령 {} \;` | 찾은 파일마다 명령 실행 |
| `-ok 명령 {} \;` | `-exec` 인데 **하나씩 물어봄** |

`{}` 는 찾은 파일 이름이 들어갈 자리이고, `\;` 는 명령이 끝났다는 표시입니다.
**`\;` 앞에 공백이 있어야 합니다.**

```bash
# 30일 넘은 로그 파일 찾기
find /var/log -type f -name "*.log" -mtime +30

# 찾아서 압축하기
find /var/log -type f -name "*.log" -mtime +30 -exec gzip {} \;

# 지우기 전에 하나씩 확인받기
find /tmp -type f -mtime +7 -ok rm {} \;

# 내 소유의 100MB 넘는 파일
find /home -user $(whoami) -size +200000
```

### 두 가지 주의

**`-name` 에 `*` 를 쓸 때는 따옴표.** 안 쓰면 셸이 먼저 해석해버려 엉뚱한 결과가 나옵니다.

```bash
find . -name *.log      # 위험 — 셸이 먼저 확장
find . -name "*.log"    # 올바름
```

**`-exec` 는 파일마다 명령을 새로 띄웁니다.** 파일이 수만 개면 느립니다.
`\;` 대신 `+` 를 쓰면 여러 개를 한 번에 넘겨 훨씬 빠릅니다.

```bash
find /var/log -name "*.log" -exec gzip {} +
```

## tar — 여러 파일을 하나로 묶기

```bash
tar [옵션] 묶음파일 대상파일...
```

**압축이 아니라 묶는 것**입니다. 여러 파일을 하나로 이어붙일 뿐 용량은 줄지 않습니다.
압축은 `gzip` 이 따로 합니다.

| 옵션 | 하는 일 |
| --- | --- |
| `c` | 묶음 만들기 (create) |
| `t` | 안에 뭐가 있는지 목록 보기 (list) |
| `x` | 풀기 (extract) |
| `f` | 묶음 파일 이름 지정 — **거의 항상 필요** |
| `v` | 진행 상황 출력 |

```bash
tar cvf backup.tar /etc/nginx     # 묶기
tar tvf backup.tar                # 뭐가 들었는지 확인
tar xvf backup.tar                # 풀기
```

**푸는 것과 만드는 것은 `c` 하나 차이**입니다. 실수로 `c` 를 쓰면 기존 묶음이
덮어써지므로, 풀기 전에 `t` 로 먼저 확인하는 습관을 들이세요.

### 묶으면서 바로 압축하기

`z` 를 붙이면 `gzip` 압축까지 한 번에 합니다.

```bash
tar czvf backup.tar.gz /etc/nginx   # 묶고 압축
tar xzvf backup.tar.gz              # 풀고 압축 해제
```

## gzip · bzip2 — 압축하기

| 압축 | 해제 | 확장자 |
| --- | --- | --- |
| `gzip 파일` | `gunzip 파일.gz` | `.gz` |
| `bzip2 파일` | `bunzip2 파일.bz2` | `.bz2` |

```bash
$ gzip file1 file2 file3
$ ls *.gz
file1.gz  file2.gz  file3.gz
```

**원본이 사라지고 압축본만 남습니다.** 원본을 남기려면 `gzip -k` 를 쓰세요.

`bzip2` 는 `gzip` 보다 더 줄지만 느립니다. 로그처럼 자주 다루는 것은 `gzip`,
오래 보관할 것은 `bzip2` 가 무난합니다.

## 이어서 익히기

```bash
# 어제 이후 수정된 설정 파일 중 'listen' 이 있는 것 찾기
find /etc -name "*.conf" -mtime -1 -exec grep -l "listen" {} +

# 로그에서 IP 별 접속 횟수 상위 10개
grep -oE "^[0-9.]+" access.log | sort | uniq -c | sort -nr | head -10
```

두 번째 예시처럼 `grep` 의 결과를 다른 명령에 넘기는 방식이
[리눅스 CLI 심층 가이드](/study/linux)의 주제입니다.
