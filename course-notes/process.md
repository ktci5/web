## 용어부터

| 말 | 무엇 |
| --- | --- |
| **프로세스** | 메모리에서 실행 중인 프로그램 |
| **데몬(Daemon)** | 부팅할 때 자동으로 떠서 계속 떠 있는 서비스 프로세스 |
| **작업(Job)** | 터미널에서 실행시킨 프로세스 |

프로그램은 디스크에 있는 파일이고, **그것을 실행해 메모리에 올라온 것이
프로세스**입니다. 같은 프로그램을 두 번 실행하면 프로세스는 두 개입니다.

데몬은 이름 끝에 `d` 가 붙는 경우가 많습니다. `sshd`, `httpd`, `systemd`.

---

## 작업 제어

셸이 직접 관리하는 프로세스를 **작업(Job)** 이라고 합니다. 각 작업에는
PID(프로세스 번호)와 별도로 **작업 번호**가 붙습니다.

### 세 가지 상태

| 상태 | 무엇 |
| --- | --- |
| **Foreground** | 터미널을 차지하고 실행. 끝날 때까지 다른 명령을 못 침 |
| **Background** | 터미널을 안 차지하고 뒤에서 실행 |
| **Suspend** | 멈춰 있는 상태 |

### 명령

```bash
$ 명령 &              # 처음부터 백그라운드로
$ jobs                # 지금 작업 목록
$ fg %1               # 1번 작업을 앞으로 가져오기
$ bg %1               # 멈춘 작업을 백그라운드에서 계속
Ctrl + Z              # 지금 작업을 멈추기
Ctrl + C              # 지금 작업을 종료
```

**실제로 이렇게 씁니다.**

```bash
$ tail -f /var/log/messages     # 실행했는데 터미널이 묶임
Ctrl + Z                        # 일단 멈추고
$ bg                            # 뒤로 보내기
$ jobs
[1]+  Running   tail -f /var/log/messages &
$ fg %1                         # 다시 앞으로
```

명령을 실행했다가 오래 걸릴 것 같으면 `Ctrl+Z` → `bg` 로 뒤로 보내고
다른 일을 하면 됩니다.

> 백그라운드로 보낸 작업도 **터미널을 닫으면 같이 죽습니다.**
> 접속을 끊어도 계속 돌려야 한다면 `nohup 명령 &` 또는 `tmux` 를 씁니다.

## 무엇이 돌고 있나 — ps

```bash
$ ps -ef              # 전체 프로세스
$ ps aux              # 같은 목적, BSD 방식 표기
$ ps -ef | grep nginx # 특정 프로세스 찾기
```

`ps -ef` 의 주요 열입니다.

| 열 | 뜻 |
| --- | --- |
| `UID` | 실행한 사용자 |
| **`PID`** | 프로세스 번호 |
| **`PPID`** | 부모 프로세스 번호 |
| `C` | CPU 사용률 |
| `STIME` | 시작 시각 |
| `TTY` | 연결된 터미널 |
| `CMD` | 실행된 명령 |

**PID 와 PPID 를 함께 보세요.** 어떤 프로세스가 무엇에서 파생됐는지 보이면
어디를 멈춰야 할지 판단이 섭니다.

### STAT — 프로세스 상태

| 글자 | 상태 |
| --- | --- |
| `R` | 실행 중 (Running) |
| `S` | 잠들어 있음 (Sleeping) — 대부분 여기 |
| **`D`** | **중단할 수 없는 대기** — 보통 디스크 I/O |
| `T` | 멈춤 (Stopped) |
| **`Z`** | **좀비** — 끝났는데 부모가 정리를 안 함 |

`D` 상태가 쌓이면 디스크가 느리다는 신호입니다.
`Z` 는 그 자체로는 자원을 거의 안 쓰지만, 계속 늘어나면 부모 프로세스에
문제가 있는 것입니다.

### 관계를 보기

```bash
$ pstree              # 부모-자식 관계를 나무 모양으로
$ pgrep -l bash       # 이름으로 PID 찾기
$ pgrep -u user1      # 특정 사용자의 프로세스
```

## 실시간으로 보기 — top

```bash
$ top
```

`top` 안에서 쓰는 키입니다.

| 키 | 하는 일 |
| --- | --- |
| `M` | **메모리(RES) 순으로 정렬** |
| `P` | **CPU 순으로 정렬** |
| `k` | 프로세스 종료 |
| `1` | CPU 코어별로 나눠 보기 |
| `h` | 도움말 |
| `q` | 종료 |

**뭔가 느리다면 `top` 을 띄우고 `P` 와 `M` 을 번갈아 눌러보세요.**
CPU 를 먹는 놈과 메모리를 먹는 놈이 각각 보입니다.

`htop` 이 설치되어 있다면 더 보기 편합니다.

## 프로세스 종료 — 시그널

`kill` 은 "죽여라"가 아니라 **"신호를 보내라"** 는 뜻입니다.

| 시그널 | 번호 | 뜻 |
| --- | --- | --- |
| `SIGHUP` | 1 | 다시 읽기 (설정 리로드에 자주 씀) |
| `SIGINT` | 2 | 중단 — `Ctrl+C` 와 같음 |
| **`SIGTERM`** | **15** | **정상 종료 요청** — 기본값 |
| `SIGKILL` | 9 | **강제 종료** — 거부할 수 없음 |

```bash
$ kill 1234              # SIGTERM (기본)
$ kill -15 1234          # 같은 뜻
$ kill -INT 1234         # SIGINT
$ kill -9 1234           # 강제 종료
$ killall -9 nginx       # 이름으로 전부
```

### -9 를 먼저 쓰지 마세요

| | `kill -15` | `kill -9` |
| --- | --- | --- |
| 프로세스가 | 정리하고 스스로 종료 | 즉시 사라짐 |
| 데이터 | 저장할 기회가 있음 | **유실 가능** |
| 임시 파일·락 | 정리됨 | **남음** |

**순서를 지키세요.**

```bash
$ kill 1234              # 먼저 정중히
$ sleep 5                # 잠시 기다리고
$ ps -p 1234             # 아직 살아 있나?
$ kill -9 1234           # 그때 강제로
```

`-9` 로 죽인 프로세스는 락 파일을 남겨서 **다시 시작이 안 되는 경우**가 있습니다.
데이터베이스에서 특히 그렇습니다.

## 정리

```bash
ps -ef | grep 이름       뭐가 돌고 있나
pstree                  부모-자식 관계
top → P / M             CPU·메모리 많이 쓰는 것
jobs / fg / bg          작업 앞뒤로 옮기기
Ctrl+Z → bg             묶인 터미널 풀기
kill 15 → 안 되면 -9    종료는 순서대로
```
