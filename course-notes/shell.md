## 셸이란

로그인하면 가장 먼저 실행되는 프로그램입니다. **사용자와 커널 사이에서 통역을
맡습니다.** 우리가 `ls` 라고 치면 셸이 그것을 해석해 커널에게 시키고, 결과를
받아 화면에 보여줍니다.

```
사용자  →  셸  →  커널  →  하드웨어
```

터미널을 열거나 콘솔에 접속할 때마다 새 셸이 시작됩니다.

### 종류

| 셸 | 만든 곳 | 특징 |
| --- | --- | --- |
| Bourne (`sh`) | AT&T Bell Labs | 원조. 작고 빠르지만 편의 기능이 적음 |
| C shell (`csh`) | UC Berkeley | C 언어풍 문법. `alias` 와 명령 기록 도입 |
| Korn (`ksh`) | AT&T Bell Labs | Bourne 의 확장. C shell 보다 빠름 |
| **bash** | GNU | Bourne Again Shell. Korn 과 C shell 의 장점을 합침 — **대부분의 리눅스 기본** |
| dash | Debian | bash 보다 가볍고 빠름. POSIX 호환 |
| zsh | | Korn 계열. macOS 기본 |

**지금 쓰는 것이 무엇인지** 확인해두세요.

```bash
$ echo $SHELL
/bin/bash
```

스크립트 첫 줄에 `#!/bin/bash` 를 쓸지 `#!/bin/sh` 를 쓸지가 이 차이에서 갈립니다.
`sh` 로 지정하면 bash 전용 문법이 동작하지 않습니다.

## 셸이 하는 세 가지 일

| 역할 | 뜻 |
| --- | --- |
| **명령 해석기** | 한 줄씩 읽어 실행. 컴파일러처럼 한꺼번에 번역하지 않음 |
| **프로그래밍 언어** | 조건·반복을 써서 스크립트로 자동화 |
| **작업 환경 제공** | 환경 변수와 설정 파일로 사용자마다 다른 환경 |

### 명령 하나가 처리되는 순서

```bash
$ ps -ef | sort +1 | more
```

셸은 이 한 줄을 이렇게 처리합니다.

1. 토큰(구성 요소)으로 쪼갠다
2. 각 토큰이 명령인지 옵션인지 연산자인지 구분한다
3. 구문 분석 순서대로 실행한다
4. 각 명령의 옵션은 그 명령이 실행될 때 적용된다

더 자세히는 **11단계**를 거칩니다.

| 순서 | 무엇 |
| --- | --- |
| 1 | 명령 읽기 |
| 2 | 키워드 (`if`, `else`, `fi`, `do`, `done`) |
| 3 | **별칭(alias)** |
| 4 | **내장 명령** (`cd`, `echo`, `bg`) |
| 5 | 함수 |
| 6 | `~` 확장 |
| 7 | 명령 치환 (`` ` ` ``, `$( )`) |
| 8 | 산술 확장 |
| 9 | **메타 문자** (`*`, `?`, `[ ]`) |
| 10 | `$PATH` 에서 명령 찾기 |
| 11 | 실행 |

**이 순서가 실무에서 의미를 갖습니다.** 9번(메타 문자 확장)이 10번(명령 찾기)보다
먼저라, `find . -name *.log` 라고 쓰면 셸이 `*.log` 를 먼저 펼쳐버려
`find` 에게는 이미 파일 이름이 넘어갑니다. 그래서 따옴표가 필요합니다.

## 리다이렉션 — 입출력 방향 바꾸기

모든 명령은 세 개의 통로를 가집니다.

| 번호 | 이름 | 무엇 |
| --- | --- | --- |
| `0` | stdin | 표준 입력 (기본: 키보드) |
| `1` | stdout | 표준 출력 (기본: 화면) |
| `2` | stderr | **표준 오류** (기본: 화면) |

출력과 오류가 **따로** 있다는 점이 핵심입니다. 둘 다 화면에 나오니 같아 보이지만
별개의 통로입니다.

| 기호 | 하는 일 |
| --- | --- |
| `>` | 출력을 파일로 (**덮어씀**) |
| `>>` | 출력을 파일 끝에 **덧붙임** |
| `<` | 파일을 입력으로 |
| `2>` | 오류만 따로 |
| `2>&1` | 오류를 출력과 같은 곳으로 |

```bash
$ ls /var /없는디렉토리 1> ls.out 2>&1
$ cat ls.out
/없는디렉토리: 해당 파일이나 디렉토리가 없음     ← stderr 였던 것
/var:                                      ← stdout
log
...
```

`2>&1` 은 "2번을 1번이 가는 곳으로 보내라"는 뜻입니다.
**순서가 중요합니다** — `2>&1 > file` 은 의도대로 안 됩니다.
`> file 2>&1` 처럼 출력 방향을 먼저 정한 뒤 오류를 합쳐야 합니다.

자주 쓰는 형태입니다.

```bash
$ 명령 > /dev/null 2>&1     # 출력도 오류도 다 버리기
$ 명령 2> /dev/null         # 오류만 숨기기
$ 명령 >> app.log 2>&1      # 전부 로그에 쌓기
```

## 파이프 — 명령을 잇기

```bash
$ who | wc -l
35
```

앞 명령의 **출력**이 뒤 명령의 **입력**이 됩니다. 접속한 사람 목록을 줄 수로 세면
몇 명이 접속했는지 나옵니다.

세미콜론은 이어서 실행할 뿐 결과를 넘기지 않습니다.

```bash
$ date ; uname -a ; who am i     # 그냥 차례로 실행
```

**파이프는 넘기고, 세미콜론은 그냥 순서대로.** 이 차이를 구분하면 됩니다.

## 메타 문자 — 파일 이름 골라내기

| 기호 | 뜻 | 예 |
| --- | --- | --- |
| `*` | 아무 글자 **0개 이상** | `f*` → `file1`, `foo`, `f` |
| `?` | 아무 글자 **정확히 하나** | `dir?` → `dir1`, `dirA` |
| `[ ]` | 괄호 안 글자 중 하나 | `[a-f]*` → a~f 로 시작하는 것 |

```bash
$ ls f*          # f 로 시작
$ ls *3          # 3 으로 끝
$ ls dir?        # dir + 한 글자
$ ls [fp]*       # f 또는 p 로 시작
$ ls [a-f]*      # a~f 로 시작
```

이것을 셸이 **미리 펼쳐서** 명령에 넘깁니다. `ls f*` 는 실제로는
`ls file1 file2 foo` 가 되어 실행됩니다.

## alias — 내 명령 만들기

```bash
$ alias 이름='명령'
```

세 가지 규칙이 있습니다.

- `=` **앞뒤에 공백을 넣으면 안 됩니다**
- 명령에 공백·메타 문자·옵션이 있으면 따옴표로 감쌉니다
- 여러 명령은 세미콜론으로 잇습니다

```bash
$ alias info='uname -a; id; date'
$ info

$ alias ll='ls -alF'
$ alias rm='rm -i'          # 실수 방지

$ alias                     # 지금 걸린 것 보기
$ unalias info              # 해제
```

**왜 쓰나요.**

- 같은 명령의 여러 버전 중 원하는 것을 고정할 때
- 자주 오타 나는 명령을 바로잡을 때
- 기본 옵션을 붙여두고 싶을 때
- 긴 명령을 짧게

터미널을 닫으면 사라집니다. 계속 쓰려면 아래 설정 파일에 적어둡니다.

## 환경 설정 파일

로그인하면 정해진 순서로 파일들이 읽힙니다.

| 파일 | 누구에게 | 무엇 |
| --- | --- | --- |
| `/etc/profile` | **모든 사용자** | 관리자가 관리하는 시스템 전체 설정 |
| `~/.bash_profile` | 나만 | 로그인할 때 한 번. 환경 변수, 터미널 설정 |
| `~/.bashrc` | 나만 | **셸을 열 때마다.** alias, 함수 |

```
로그인 → /etc/profile → ~/.bash_profile → ~/.bashrc → $
```

**둘을 어떻게 나눠 쓰나요.**

- `~/.bash_profile` — 한 번만 하면 되는 것 (`PATH`, `EDITOR` 같은 환경 변수)
- `~/.bashrc` — 셸마다 필요한 것 (`alias`, 프롬프트)

`/etc/skel` 은 새 사용자를 만들 때 홈 디렉터리에 복사되는 원본입니다.
여기에 파일을 넣어두면 앞으로 만들어지는 계정이 그것을 갖고 시작합니다.

### 고친 뒤에는

파일을 고쳐도 **이미 열린 셸에는 적용되지 않습니다.** 다시 읽어야 합니다.

```bash
$ source ~/.bashrc
$ . ~/.bashrc        # 같은 뜻, 짧은 형태
```

## 변수

### 쓰는 법

| 하는 일 | 명령 |
| --- | --- |
| 설정 | `VAR=값` |
| 자식 프로세스에도 물려주기 | `export VAR=값` |
| 해제 | `unset VAR` |
| 전체 보기 | `set`, `env`, `export` |
| 값 확인 | `echo $VAR` |

**`=` 앞뒤에 공백을 넣으면 안 됩니다.** `VAR = 값` 은 `VAR` 라는 명령을
실행하려는 것으로 해석됩니다.

### 지역 변수와 전역 변수

이게 `export` 가 필요한 이유입니다.

```bash
$ hhs=1              # 지역 — 지금 셸에서만
$ bash               # 자식 셸을 띄우면
$ echo $hhs          # 비어 있음
$ exit

$ hhs=1
$ export hhs         # 전역으로 승격
$ bash
$ echo $hhs          # 1 — 물려받음
```

**변수는 자식에게만 흐르고 부모로 거슬러 오르지 않습니다.** 스크립트 안에서
`cd` 를 해도 실행을 마치고 나면 원래 자리인 이유가 이것입니다.
스크립트는 자식 셸에서 돌기 때문입니다. 그래서 환경을 바꾸는 스크립트는
`source` 로 실행합니다.

### 알아둘 환경 변수

| 변수 | 무엇 |
| --- | --- |
| `PATH` | **명령을 찾을 디렉터리 목록.** 콜론으로 구분 |
| `HOME` | 홈 디렉터리. `cd` 를 인자 없이 쓰면 여기로 |
| `LOGNAME` | 로그인 이름 |
| `SHELL` | 지금 쓰는 셸 |
| `EDITOR` | 기본 편집기 |
| `PS1` | 주 프롬프트 (`$`) |
| `PS2` | 보조 프롬프트 (`>`) — 줄이 안 끝났을 때 |
| `TERM` | 터미널 유형 |
| `DISPLAY` | 그래픽 프로그램을 띄울 위치 |

`PATH` 가 가장 자주 문제를 일으킵니다. **명령을 못 찾는다면 대개 `PATH` 입니다.**

```bash
$ echo $PATH
/usr/local/bin:/usr/bin:/bin

$ export PATH=$PATH:/opt/myapp/bin     # 뒤에 추가
$ which python3                        # 어느 것이 실행되는지
```

`$PATH:` 로 시작해 기존 것을 살리는 게 중요합니다. 그냥 `PATH=/opt/bin` 이라고
하면 기존 경로가 전부 날아가 `ls` 조차 안 됩니다.

## 따옴표

셸이 메타 문자를 해석하지 않게 막는 장치입니다. **이걸 모르면 스크립트에서
계속 막힙니다.**

| 기호 | 무엇 |
| --- | --- |
| `' '` | 안의 모든 메타 문자를 **글자 그대로** |
| `" "` | `$`, `` ` ``, `\` **셋만 살리고** 나머지는 글자 그대로 |
| `\` | 바로 뒤 한 글자만 글자 그대로 |
| `` `명령` `` | 명령을 실행해 그 결과로 바꿈 |
| `$(명령)` | 위와 같음 — **이쪽을 권장** |

```bash
$ num=19
$ echo "$num"        # 19    — 큰따옴표는 변수를 살림
$ echo '$num'        # $num  — 작은따옴표는 글자 그대로

$ name=hhs
$ echo "hello \$name"          # hello $name  — \ 로 막음
$ echo "The time is $(date +%H:%M)."
The time is 14:32.
```

`` `명령` `` 보다 `$(명령)` 을 쓰세요. 중첩이 가능하고 눈에도 잘 띕니다.

```bash
$ echo "오늘은 $(date +%Y년\ %m월\ %d일) 입니다"
```

**언제 무엇을 쓰나.**

- 변수를 쓸 것이다 → `" "`
- 있는 그대로 넘길 것이다 → `' '`
- 한 글자만 막을 것이다 → `\`

## 정리

```bash
echo $SHELL                지금 쓰는 셸
명령 > file 2>&1           출력과 오류를 함께 파일로
명령1 | 명령2               앞의 결과를 뒤로 넘기기
alias ll='ls -alF'         내 명령 만들기
export VAR=값              자식에게도 물려주기
source ~/.bashrc           설정 다시 읽기
echo "$VAR"  vs  echo '$VAR'   따옴표에 따라 달라짐
$(명령)                     명령 결과를 값으로
```

이어집니다.
