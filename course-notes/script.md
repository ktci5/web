## 스크립트란

**명령과 주석으로 이뤄진 그냥 텍스트 파일**입니다. 특별한 형식이 없어서
평소 치던 명령을 그대로 적으면 됩니다.

```bash
$ vi ls.sh
```

```bash
#!/bin/sh
# 디렉터리 목록을 보여준다
ls -l          # 이렇게 명령 뒤에 주석을 달아도 됩니다
```

```bash
$ chmod +x ls.sh      # 실행 권한 주기
$ ./ls.sh             # 실행
```

**`chmod +x` 를 빼먹으면 "Permission denied"** 가 납니다. 스크립트를 처음 만들 때
가장 많이 겪는 일입니다.

`./` 를 붙이는 이유는 현재 디렉터리가 보통 `PATH` 에 없기 때문입니다.
`ls.sh` 라고만 치면 셸이 `PATH` 에서 찾다가 못 찾습니다.

## 첫 줄 — 셔뱅(`#!`)

```bash
#!/bin/bash
```

**이 스크립트를 어느 셸로 실행할지** 지정합니다.

- 반드시 **첫 줄**에, 앞에 빈 줄이나 공백이 없어야 함
- 원하는 기능을 지원하는 셸을 고를 것
- **부팅 스크립트는 POSIX 셸(`/bin/sh`)** 을 쓰는 것이 안전

| 지정 | 쓸 수 있는 것 |
| --- | --- |
| `#!/bin/sh` | POSIX 표준 문법만. 이식성이 높음 |
| `#!/bin/bash` | 배열, `[[ ]]` 등 bash 확장 문법까지 |

`#!/bin/sh` 로 써놓고 bash 문법을 쓰면 **다른 시스템에서 갑자기 실패합니다.**
Ubuntu 의 `/bin/sh` 는 dash 라 bash 문법이 없습니다.

## 주석

`#` 으로 시작합니다. 줄 처음이든 명령 뒤든 상관없습니다.

```bash
# 이 스크립트는 로그를 정리합니다     ← 보통 위쪽에 설명
rm -f /tmp/*.log   # 임시 로그 삭제   ← 명령 뒤에도 가능
```

**나중에 고칠 사람(대개 자기 자신)을 위해 씁니다.** 무엇을 하는지보다
**왜 그렇게 했는지**를 적으면 훨씬 도움이 됩니다.

## 디버깅

스크립트가 뜻대로 안 될 때 씁니다.

| 옵션 | 하는 일 |
| --- | --- |
| `-x` | 변수와 메타 문자를 **치환한 뒤** 실행되는 줄을 출력 |
| `-v` | **치환하기 전** 원본 그대로 출력 |
| `-n` | 실행하지 않고 문법만 검사 |
| `-f` | 파일 이름 확장(`*`) 끄기 |
| `+x` | `-x` 끄기 |

```bash
$ bash -x ./myscript.sh          # 실행 과정 추적
$ bash -n ./myscript.sh          # 문법만 확인
```

스크립트 안에서 일부 구간만 볼 수도 있습니다.

```bash
set -x
문제가 있는 구간
set +x
```

**`-x` 가 가장 유용합니다.** 변수에 실제로 무엇이 들어갔는지 보이기 때문에,
"왜 빈 값이지" 같은 문제가 바로 드러납니다.

## 조건 연산자 — `&&` 와 `||`

앞 명령의 **성공 여부**에 따라 다음을 실행할지 정합니다.

| 연산자 | 언제 뒤를 실행하나 |
| --- | --- |
| `&&` | 앞이 **성공**했을 때 |
| `\|\|` | 앞이 **실패**했을 때 |

```bash
$ pwd
/home/user1

$ mkdir $HOME/newdir && cd $HOME/newdir
$ pwd
/home/user1/newdir
```

디렉터리를 만드는 데 성공했으니 `cd` 가 실행됐습니다.

```bash
$ mkdir /usr/tmp/newdir || mkdir $HOME/newdir1
```

앞이 실패하면 뒤를 실행합니다. **대안을 두는 방식**입니다.

실무에서 자주 보이는 형태입니다.

```bash
# 성공했을 때만 다음 단계로
$ ./build.sh && ./deploy.sh

# 실패하면 알림
$ ./backup.sh || echo "백업 실패" | mail -s "경고" admin@example.com

# 디렉터리가 없으면 만들기
$ [ -d /data ] || mkdir -p /data
```

## 인자 받기

스크립트에 값을 넘길 수 있습니다.

```bash
$ ./com.sh hello world
              ↑     ↑
             $1    $2
```

```bash
#!/bin/sh
echo $1 $2       # hello world
shift            # 한 칸씩 당김
echo $1 $2       # world
```

`shift` 는 인자를 왼쪽으로 밀어 `$2` 였던 것이 `$1` 이 됩니다.
인자를 하나씩 처리할 때 씁니다.

### 위치 변수

| 변수 | 무엇 |
| --- | --- |
| `$0` | **스크립트 이름** |
| `$1` ~ `$9` | 1~9번째 인자 |
| `${10}` 이상 | 10번째부터는 중괄호 필요 |
| `$#` | **인자 개수** |
| `$@` · `$*` | 인자 전부 |
| `${#변수}` | 값의 길이 |

Bourne shell 은 `$9` 까지만 지원해서 `${10}` 표기가 생겼습니다.

### 인자 검사

인자를 안 주고 실행하는 실수가 흔합니다. 앞에서 막아두면 좋습니다.

```bash
#!/bin/bash
if [ $# -lt 1 ]; then
  echo "사용법: $0 <파일명>"
  exit 1
fi

echo "$1 을 처리합니다"
```

`$0` 을 쓰면 스크립트 이름이 바뀌어도 안내 문구가 따라갑니다.

### `$@` 와 `$*` 의 차이

거의 같아 보이지만 따옴표로 감쌀 때 달라집니다.

| | `"$@"` | `"$*"` |
| --- | --- | --- |
| 결과 | 인자마다 따로 | 전부 하나로 합침 |

**공백이 든 파일 이름을 다룰 때는 `"$@"`** 를 쓰세요. `"$*"` 는 하나로 합쳐져
파일 하나로 취급됩니다.

## 처음 쓸 때 걸리는 것들

```bash
VAR = 값        # 틀림 — = 앞뒤에 공백 금지
VAR=값          # 맞음
```

```bash
$ ./script.sh
-bash: ./script.sh: Permission denied
$ chmod +x script.sh      # 실행 권한
```

```bash
$ ./script.sh
-bash: ./script.sh: /bin/bash^M: bad interpreter
```

마지막은 **윈도우에서 만든 파일**을 리눅스에서 실행할 때 납니다.
줄바꿈 문자가 달라서인데, 이렇게 고칩니다.

```bash
$ dos2unix script.sh
$ sed -i 's/\r$//' script.sh     # dos2unix 가 없을 때
```

## 정리

```bash
#!/bin/bash            첫 줄에 셸 지정
chmod +x script.sh     실행 권한
./script.sh            실행
bash -x script.sh      문제가 있을 때 추적
명령1 && 명령2          성공하면 다음
명령1 || 명령2          실패하면 대안
$1 $2 $# $@            인자 받기
```
