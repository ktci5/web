## 시작하기 전에

리눅스는 **모든 것을 파일로 다룹니다.** 문서도 파일이고, 디렉터리도 파일이고,
연결된 디스크나 키보드조차 파일로 보입니다. 그래서 파일을 다루는 명령 몇 개만
익히면 시스템 대부분을 만질 수 있습니다.

### 파일의 네 가지 유형

| 유형 | 무엇 | `ls -l` 첫 글자 |
| --- | --- | --- |
| 일반 파일 (Regular) | 문서, 실행 파일, 이미지 | `-` |
| 디렉터리 (Directory) | 파일을 담는 상자 | `d` |
| 심볼릭 링크 (Symbolic link) | 다른 파일을 가리키는 바로가기 | `l` |
| 장치 파일 (Device) | 디스크·터미널 같은 하드웨어 | `b` 또는 `c` |

## 명령을 쓰는 법

```bash
$ 명령  옵션  인자
```

| 부분 | 무엇 | 예 |
| --- | --- | --- |
| 명령 | 무엇을 할지 | `ls` |
| 옵션 | 어떻게 할지. `-` 나 `--` 로 시작 | `-l`, `--all` |
| 인자 | 무엇에 대해 할지 | `/etc` |

네 가지 조합이 가능합니다. `ls` (명령만) · `ls -l` (옵션) · `ls /etc` (인자) ·
`ls -l /etc` (둘 다).

### 알아두면 편한 키

| 키 | 하는 일 |
| --- | --- |
| `Tab` | 파일·디렉터리·명령 이름 **자동 완성** |
| `↑` `↓` | 이전에 친 명령 불러오기 |
| `Ctrl + C` | 실행 중인 명령 강제 종료 |
| `Ctrl + U` | 지금 치던 줄 전체 지우기 |
| `Ctrl + D` | 입력 끝 표시 (로그아웃에도 쓰임) |

**`Tab` 을 습관으로 만드세요.** 긴 경로를 다 치지 않아도 되고, 오타로 인한 실수도
줄어듭니다. 여러 후보가 있으면 `Tab` 을 두 번 눌러 목록을 봅니다.

세미콜론으로 여러 명령을 이어 쓸 수 있습니다.

```bash
$ cd /var/log ; ls -l ; pwd
```

## 모르면 man

명령 사용법이 기억나지 않을 때 인터넷보다 빠릅니다.

```bash
$ man ls              # ls 설명서
$ man -k passwd       # passwd 가 들어간 설명서 찾기 (apropos)
$ man 5 passwd        # 5번 섹션의 passwd
```

### 섹션 번호가 있는 이유

같은 이름이 여러 뜻을 가질 수 있습니다. `passwd` 는 **명령**이기도 하고
**설정 파일**(`/etc/passwd`)이기도 합니다.

| 번호 | 무엇 |
| --- | --- |
| 1 | 일반 명령 |
| 2 | 시스템 콜 |
| 3 | 라이브러리 함수 |
| 4 | 특수 파일 (`/dev` 아래) |
| 5 | **파일 형식과 설정 파일** |
| 6 | 게임 |
| 7 | 기타 |
| 8 | 시스템 관리 명령 |
| 9 | 커널 루틴 |

`man passwd` 는 1번(명령)을 보여주고, 설정 파일을 보려면 `man 5 passwd` 라고
섹션을 지정합니다.

### 설명서 안에서 움직이기

| 키 | 하는 일 |
| --- | --- |
| `Space` | 다음 화면 |
| `Enter` | 한 줄 아래로 |
| `b` | 한 화면 뒤로 |
| `/찾을말` | 검색 |
| `n` | 다음 검색 결과 |
| `q` | 나가기 |

## 어디에 있는지 — pwd, cd

```bash
$ pwd
/home/linux
```

### 경로 기호

| 기호 | 뜻 |
| --- | --- |
| `.` | 지금 있는 디렉터리 |
| `..` | 한 단계 위 |
| `~` | 내 홈 디렉터리 |
| `~user1` | user1 의 홈 디렉터리 |
| `-` | **바로 전에 있던 곳** |

`cd -` 가 특히 유용합니다. 멀리 갔다가 원래 자리로 한 번에 돌아옵니다.

### 절대 경로와 상대 경로

| 방식 | 시작 | 예 |
| --- | --- | --- |
| 절대 경로 | 항상 `/` 로 시작 | `/var/log` |
| 상대 경로 | 지금 위치 기준 | `../../var/log` |

```bash
$ pwd
/home/linux

$ cd ../../var/log     # 상대 — 두 단계 올라가서 var/log 로
$ cd -                 # 아까 있던 /home/linux 로 복귀
$ cd /var/log          # 절대 — 어디에 있든 같은 곳
```

**스크립트에는 절대 경로를 쓰세요.** 상대 경로는 실행 위치에 따라 결과가 달라져
"내 컴퓨터에서는 됐는데" 의 흔한 원인이 됩니다.

## 목록 보기 — ls

```bash
$ ls -l file1
-rw-r--r--  1 user1 other  1319  3월 15 11:23  file1
```

한 줄에 일곱 가지가 들어 있습니다.

| 부분 | 뜻 |
| --- | --- |
| `-` | 파일 유형 (`-` 파일, `d` 디렉터리, `l` 링크) |
| `rw-r--r--` | 권한 |
| `1` | 하드 링크 수 |
| `user1` | 소유자 |
| `other` | 그룹 |
| `1319` | 크기 (바이트) |
| `3월 15 11:23` | 마지막 수정 시각 |

### 자주 쓰는 옵션

| 옵션 | 하는 일 |
| --- | --- |
| `-l` | 자세히 보기 |
| `-a` | 숨김 파일(`.` 으로 시작)까지 |
| `-h` | 크기를 읽기 쉽게 (`1319` → `1.3K`) |
| `-t` | 수정 시각 순으로 |
| `-F` | 유형을 기호로 표시 |
| `-R` | 하위 디렉터리까지 전부 |
| `-ld` | 디렉터리 **자체**의 정보 (안의 목록이 아니라) |
| `-lL` | 심볼릭 링크가 **가리키는 대상**의 정보 |

`-F` 가 붙이는 기호입니다.

| 기호 | 유형 |
| --- | --- |
| `/` | 디렉터리 |
| `*` | 실행 파일 |
| `@` | 심볼릭 링크 |
| (없음) | 일반 파일 |

가장 많이 쓰는 조합입니다.

```bash
$ ls -lah          # 자세히 + 숨김 + 읽기 쉬운 크기
$ ls -lt | head    # 최근에 바뀐 것부터 10개
```

**`-ld` 를 기억해두세요.** 디렉터리에 `ls -l` 을 쓰면 그 **안의 목록**이 나옵니다.
디렉터리 자체의 권한을 보려면 `-d` 가 필요합니다.

```bash
$ ls -ld /var/log
drwxr-xr-x. 12 root root 4096  8월 28 09:11 /var/log
```

## 내용 보기

```bash
$ file 파일명
```

먼저 `file` 로 무엇인지 확인하는 게 안전합니다. 바이너리를 `cat` 하면 터미널이
깨질 수 있습니다.

| 명령 | 언제 |
| --- | --- |
| `cat` | 짧은 파일 전부 |
| `less` | 긴 파일을 넘겨가며 (`q` 로 종료) |
| `head -n 20` | 앞부분만 |
| `tail -n 20` | 뒷부분만 |
| `tail -f` | **새로 쌓이는 줄을 실시간으로** |
| `strings` | 바이너리에서 읽을 수 있는 글자만 |

`tail -f` 는 로그를 볼 때 거의 항상 씁니다.

```bash
$ tail -f /var/log/messages
```

터미널이 깨졌다면 당황하지 말고 `reset` 을 치면 돌아옵니다.

## 만들기 · 복사 · 이동 · 지우기

### 만들기

```bash
$ touch file1 file2 file3      # 빈 파일 (이미 있으면 시각만 갱신)
$ mkdir dir1                   # 디렉터리
$ mkdir -p a/b/c               # 중간 경로까지 한 번에
```

`-p` 가 없으면 `a` 가 없을 때 `a/b/c` 를 못 만듭니다.

### 복사

```bash
$ cp 원본 사본                  # 파일
$ cp file1 file2 dir/          # 여러 개를 디렉터리로
$ cp -r dir1 dir2              # 디렉터리는 -r 필요
```

`-r` 은 recursive, 안에 든 것까지 따라간다는 뜻입니다.

### 이동과 이름 변경

**`mv` 하나가 둘 다 합니다.** 대상이 기존 디렉터리면 이동, 아니면 이름 변경입니다.

```bash
$ mv file1 /tmp/               # 이동
$ mv file1 file2               # 이름 변경
$ mv dir1 /tmp/                # 디렉터리 이동 (-r 불필요)
$ mv dir1 dir2                 # 디렉터리 이름 변경
```

### 지우기

```bash
$ rm file1 file2               # 파일
$ rmdir empty_dir              # 빈 디렉터리만
$ rm -r dir                    # 안에 든 것까지
```

> **리눅스에는 휴지통이 없습니다.** `rm` 은 되돌릴 수 없습니다.
> 특히 `rm -rf` 를 변수와 함께 쓸 때는 변수가 비어 있으면 엉뚱한 곳을 지웁니다.
> 익숙해지기 전에는 `rm -i` 로 하나씩 확인받는 습관이 안전합니다.

## 링크 — 하나의 파일, 여러 이름

### 심볼릭 링크

```bash
$ ln -s 원본 링크이름
```

바로가기입니다. **원본의 경로를 적어둔 작은 파일**이라, 원본이 사라지면
링크는 남지만 아무것도 가리키지 못합니다(끊어진 링크).

```bash
$ ln -s /app/releases/v1.0.0 /app/current
$ ls -l /app/current
lrwxrwxrwx 1 root root 22  8월 28 10:00 /app/current -> /app/releases/v1.0.0
```

무중단 배포에서 자주 쓰는 방식입니다. 링크가 가리키는 곳만 바꾸면 전환됩니다.

### 하드 링크

```bash
$ ln 원본 링크이름
```

같은 **inode** 를 가리키는 또 하나의 이름입니다. 원본과 링크가 대등해서
어느 쪽을 지워도 나머지가 남습니다.

| | 심볼릭 링크 | 하드 링크 |
| --- | --- | --- |
| 만드는 법 | `ln -s` | `ln` |
| 가리키는 것 | 경로 | inode |
| 원본을 지우면 | 끊어짐 | 남아 있음 |
| 디렉터리 | 가능 | 불가능 |
| 다른 파티션 | 가능 | 불가능 |

### 파일은 세 부분으로 되어 있습니다

| 구성 | 담긴 것 |
| --- | --- |
| 파일 이름 | 사람이 부르는 이름 |
| **inode** | 권한·소유자·크기·시간, 그리고 데이터 위치 |
| 데이터 블록 | 실제 내용 |

**이름은 inode 를 가리키는 꼬리표일 뿐입니다.** 하드 링크가 가능한 이유이고,
`ls -l` 의 링크 수가 그 inode 를 가리키는 이름의 개수입니다.

## 권한

```bash
$ ls -l file1
-rw-r--r--  1 user1 other  1319  3월 15 11:23  file1
 ↑└┬┘└┬┘└┬┘
 유형 소유자 그룹 기타
```

첫 글자를 뺀 아홉 자리를 셋씩 끊어 읽습니다.

| 자리 | 누구 |
| --- | --- |
| 1~3 | **소유자** (user) |
| 4~6 | **그룹** (group) |
| 7~9 | **나머지 모두** (other) |

| 글자 | 파일에서 | 디렉터리에서 |
| --- | --- | --- |
| `r` | 내용을 보고 복사할 수 있음 | `ls` 로 목록을 볼 수 있음 |
| `w` | 내용을 고칠 수 있음 | 파일을 **추가·삭제**할 수 있음 |
| `x` | 실행할 수 있음 | `cd` 로 **들어갈 수 있음** |
| `-` | 안 됨 | 안 됨 |

**디렉터리의 `x` 가 헷갈립니다.** 디렉터리에서 `x` 는 "실행"이 아니라
**들어갈 수 있는지**를 뜻합니다. `r` 만 있고 `x` 가 없으면 목록은 보이지만
그 안으로 못 들어갑니다.

또 하나 — **파일을 지울 수 있는지는 그 파일이 아니라 담긴 디렉터리의 `w`** 가
결정합니다. 읽기 전용 파일이라도 디렉터리에 쓰기 권한이 있으면 지워집니다.

### 권한 바꾸기 — chmod

```bash
$ chmod 권한 파일명
```

**숫자로 주기.** `r=4`, `w=2`, `x=1` 을 더합니다.

| 숫자 | 권한 | 뜻 |
| --- | --- | --- |
| `644` | `rw-r--r--` | 소유자는 읽고 쓰기, 나머지는 읽기만 — **일반 파일 기본** |
| `755` | `rwxr-xr-x` | 소유자는 다 되고 나머지는 읽고 실행 — **디렉터리·실행 파일 기본** |
| `751` | `rwxr-x--x` | |
| `775` | `rwxrwxr-x` | 그룹까지 쓰기 허용 |
| `777` | `rwxrwxrwx` | **모두에게 전부** — 쓰지 마세요 |

**기호로 주기.** 지금 권한에서 더하거나 뺍니다.

| 대상 | 연산 | 권한 |
| --- | --- | --- |
| `u` 소유자 | `+` 추가 | `r` 읽기 |
| `g` 그룹 | `-` 제거 | `w` 쓰기 |
| `o` 나머지 | `=` 지정 | `x` 실행 |
| `a` 전부 | | |

```bash
$ chmod 755 deploy.sh          # 숫자로
$ chmod +x deploy.sh           # 실행 권한만 추가
$ chmod g+w shared/            # 그룹에 쓰기 추가
$ chmod o-rwx secret.txt       # 나머지 사용자 권한 전부 제거
```

> `chmod 777` 은 권한 문제를 "해결"한 것처럼 보이지만 누구나 고치고 지울 수
> 있게 만듭니다. 문제가 생기면 **어느 권한이 부족한지 찾는 편**이 맞습니다.
> 파일은 `644`, 디렉터리는 `755` 를 기본으로 두세요.

## 정리

가장 자주 쓰게 될 것들입니다.

```bash
pwd                    지금 어디
ls -lah                뭐가 있나 (자세히·숨김·읽기 쉽게)
cd -                   아까 그곳으로
file 파일명             이게 뭔가
less 파일명             넘겨가며 읽기
tail -f 로그            실시간으로 보기
cp -r / mv / rm -r     복사·이동·삭제
ln -s 원본 링크         바로가기 만들기
chmod 644 / 755        권한 맞추기
```

명령을 조합해 흐름을 만드는 방법은
[리눅스 CLI 심층 가이드](/study/linux)에서 이어집니다.
